# VLabs — Apparatus Inventory (3D-model worklist)

Generated by scanning all `03-apparatus.ts` files under `src/labs/semesters/`.
Source of truth for what hardware the virtual labs claim to use, and which of it
still needs Three.js geometry.

**Scan result:** 60 experiment folders, 61 `03-apparatus.ts` files, **465 line items**,
169 distinct name strings → **27 canonical physical objects** + 43 non-physical items.

## How apparatus reaches the 3D view

```
03-apparatus.ts        ApparatusSection { items: [{name, specification, quantity}] }
        ↓
ApparatusScene.tsx     buildItemModel(item)  ← matches item.name + specification
        ↓
src/components/<x>/    buildXStandalone()    ← actual Three.js geometry
```

`buildItemModel()` ends in `return buildResistorStandalone(470);` — **any apparatus name
it does not recognise is silently rendered as a resistor.** That catch-all, not the raw
name list, is what defines the real modelling backlog.

## Known mis-mappings in `buildItemModel()`

These are live bugs, not just missing art — the wrong model is already being drawn:

1. A generic diode apparatus item without a recognized part number now defaults to a 1N4148 model.
2. `ApparatusScene.tsx` — the `meter` substring means ammeter and voltmeter both match
   and render as a full digital multimeter.
3. No branch for transistor / MOSFET / op-amp / 7-segment / transformer / CRO / function
   generator / DIP switch / logic analyser → all fall to the resistor fallback.
4. `buildSwitchStandalone`, `buildPushButtonStandalone`, `buildMcuTrainerStandalone` and
   `buildLongBreadboardStandalone` are exported from `src/components/index.ts` but never
   imported by `ApparatusScene.tsx`.
5. `buildDip14Standalone('IC')` is called for every IC with a hard-coded `'IC'` label, so
   74HC00 and 74HC283 are indistinguishable on screen.

## Non-physical items (no 3D model required)

Textbooks and reference sheets (Digital Logic Design, Boolean Algebra, 2's Complement,
Half/Full Adder, Logic Gate, K-map), stationery (pencil, graph paper, calculator), and
software/toolchain (C compiler, IDE or text editor, terminal, hex editor, file-system
access, circuit simulator).

Semester 3's CPU/cache labs also list **virtual** blocks — ALU, Control Unit, Register
File, Instruction Register, Program Counter, Flag Register, Address/Data Registers, Main
Memory Model, Direct-Mapped / Fully-Associative Cache, Tag Comparator Array, LRU State
Machine, Hit/Miss Counters, 16×16 Memory Map Display. These are simulator panels rendered
from `src/labs/simulations/*`, not hardware — do not model them.

## Suggested modelling order

1. **Diode + Zener + transistor/MOSFET + op-amp** — small parts, high lab coverage, and
   they are currently drawn incorrectly.
2. **Parametric DIP builder (DIP-8/14/16/20)** — replaces `buildDip14` everywhere and
   fixes the IC label problem in one go.
3. **DIP switch + wire the 3 existing unused builders** (`switch`, `button`, `mcu-trainer`)
   into `buildItemModel()` — pure plumbing, 17 labs covered.
4. **Bench instruments: CRO, function generator, transformer** — 13 labs, biggest art effort.
5. **Panel meters (ammeter, voltmeter), probe, rheostat, logic analyser, 7-segment display.**
